# 热血传奇 Go 重制版 — 开发计划

> 基于 `asset/delphi/` 源码（commit 98711da）与 Go 实现的逐行对照。

## 当前状态

**Phase 6-11 全部完成 + 服务端深度完善 + 第一批断点修复已完成，总体完成度约 70-75%。**

已实现完整游戏循环：登录→选服→选角→进游戏→移动(速度限制+鼠标寻路)→打怪(12种AI行为+掉落表)→穿装备(重量+特殊戒指+套装)→放技能(毒/隐身/盾/击退/群疗/召唤/火墙持久事件/训练)→NPC脚本引擎(30动作/17条件)→商店买卖修理(服务端)→聊天(含行会!~前缀)→组队→交易→行会→PK(惩罚+红名)→骑马(FeatureEx编码)→GM命令→地图切换→光照→魔法特效(按efftype分发)→门交互→地图事件→完整数据保存。

第一批断点修复(2026-07)：TCP粘包重组、HandleHit技能校验、4个客户端回调接线、翅膀渲染接线、行会聊天、仓库存档完整化、火墙持久事件(SM_SHOWEVENT)、魔法投射物分发、耐久通知(SMDuraChange)、骑马外观编码。

仍为占位/缺失的深层机制：攻城战(0%)、宠物/召唤归属系统(召唤兽无主)、UI面板交互(有渲染无拖拽/点击)、中文输入(仅ASCII)、声音系统(0%)、武器升级/极品属性、物品制造链(采矿/制药/屠宰)、技能开关消息(+PWR/+LNG等)。

## 设计原则

1. **6Bit 编码保真** — 精确复刻 Delphi 算法，不重新设计
2. **单端口统一监听** — 内部路由登录/选角/游戏消息
3. **单线程游戏循环** — 10 tick/s，避免并发修改游戏状态
4. **每连接双协程** — read loop + write loop，channel 传递消息
5. **自建客户端渲染** — OpenGL 3.3，不使用 ImGui（查看器工具除外）
6. **WIL 懒加载** — Load() 只读索引，图像首次访问时解码，Destroy() 关闭句柄
7. **本地预测+ActionLock** — 客户端立即执行移动，服务端 +GOOD/+FAIL 确认/回滚
